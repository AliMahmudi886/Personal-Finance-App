# Deployment and recovery

Run the WSGI entry point from the project directory. Use a stable secret generated by a secret manager, set `FINANCE_DB_PATH` to a private persistent volume and persist the Flask instance directory for uploaded images. Keep TLS on at the proxy and use the default secure session cookie. On a single host, the runtime can be started with the following command.

```text
waitress-serve --listen=127.0.0.1:8000 app:app
```

Serve application routes through the WSGI server. A frontend proxy serving files itself must also block the legacy profile-image directories and keep the instance directory outside document roots. Use HTTPS, and arrange reverse-proxy forwarding so that Flask sees the public scheme and origin for CSRF validation. Limit login traffic at the proxy. Configure any proxy trust only for infrastructure you control.

Before deploying this branch, inventory the actual database and profile-image paths. Take an SQLite Online Backup API snapshot or quiesce writers before making a filesystem copy. Preserve the associated instance files. Restore into a separate directory, run SQLite integrity checks and confirm the application can read synthetic validation records before using the procedure on production. Retain a previous application build and database snapshot. A rollback to an older build needs review because the old session and static-upload behavior is weaker. Rotating the session key invalidates existing cookies.

No production host, backup retention policy or monitoring stack was available in the repository. The health signal used in this cycle is a successful HTTP response from the WSGI server using a temporary database.
